# One-Click ELK Infra — Terraform + Jenkins + Ansible

Provisions the AWS architecture from the diagram (Mumbai / ap-south-1, 2-AZ HA)
and installs Elasticsearch + Kibana on the app nodes using the provided
Ansible role — triggered by a single Jenkins pipeline run.

```
Client → ALB (public) → Target Group → Auto Scaling Group (private subnets)
                                          └─ Elasticsearch + Kibana (Ansible)
Admin  → Bastion (public) → SSH jump → private app nodes
Terraform state → S3 bucket (kept simple, no DynamoDB lock table)
```

## Folder structure

```
one-click-elk-infra/
├── Jenkinsfile                     # the one-click pipeline
├── terraform/
│   ├── backend-setup/              # run ONCE, manually — creates the S3 state bucket + lock table
│   ├── provider.tf
│   ├── backend.tf                  # partial S3 backend config (values passed at `init` time)
│   ├── variables.tf
│   ├── vpc.tf                      # VPC, subnets, IGW, NAT, route tables
│   ├── nacl.tf                     # Private-NACL
│   ├── security_groups.tf          # bastion-sg, alb-sg, app-sg
│   ├── bastion.tf                  # Bastion Host EC2
│   ├── alb.tf                      # ALB + target group + listener
│   ├── launch_template.tf          # app node launch template
│   ├── asg.tf                      # Auto Scaling Group (min 2 / spans both AZs)
│   └── outputs.tf
├── ansible/                         # your uploaded role, lightly adapted
│   ├── playbook.yml
│   ├── ansible.cfg
│   ├── inventory/hosts.ini.example # real hosts.ini is generated by CI, not committed
│   └── roles/{elasticsearch,kibana}/...
└── scripts/
    └── generate_inventory.sh       # builds ansible inventory from Terraform + AWS CLI output
```

## One-time setup

### 1. Create the Terraform state backend
```bash
cd terraform/backend-setup
terraform init
terraform apply           # creates just the S3 bucket for state
```
Keep this folder's local `terraform.tfstate` safe — it's the only state that
isn't stored remotely (chicken-and-egg: the bucket can't hold its own state
before it exists).

Kept intentionally simple — no DynamoDB lock table. Fine for solo/small-team
use; just avoid triggering two `apply`/`destroy` runs at the same time.

### 2. Add Jenkins credentials
| Credential ID | Type | Value |
|---|---|---|
| `aws-elk-creds` | AWS Credentials | IAM user/role with EC2, VPC, ELB, AutoScaling, S3 permissions |
| `elk-ec2-ssh-key` | SSH Username with private key | The `.pem` key matching `KEY_PAIR_NAME` |
| `elk-admin-cidr` | Secret text | Your office/VPN IP as CIDR, e.g. `1.2.3.4/32` |
| `elk-elastic-admin-pw` | Secret text | Elasticsearch `admin` superuser password |
| `elk-anonymous-pw` | Secret text | Kibana anonymous-viewer user password |
| `elk-kibana-system-pw` | Secret text | Password for the built-in `kibana_system` user |

### 3. Create an EC2 key pair (if you don't already have one)
```bash
aws ec2 create-key-pair --key-name my-ec2-keypair \
  --query 'KeyMaterial' --output text > my-ec2-keypair.pem
```
Import the private key into Jenkins as `elk-ec2-ssh-key`.

## Running it — "one click"

1. Point a Jenkins Pipeline job at this repo (Jenkinsfile at repo root).
2. Build with parameters:
   - `ACTION` = `apply`
   - `KEY_PAIR_NAME` = your key pair name
   - `TF_STATE_BUCKET` = must match step 1
   - `AWS_REGION` = `ap-south-1`
3. Approve the Terraform plan when prompted (or set `AUTO_APPROVE=true`).
4. Pipeline will:
   - `terraform apply` → VPC, subnets, NAT, bastion, ALB, ASG of app nodes
   - Discover the new app nodes' private IPs via the AWS CLI
   - Generate an Ansible inventory that SSHes through the bastion (no direct
     SSH exposure to private nodes)
   - Run `playbook.yml` → installs & secures Elasticsearch + Kibana on each node
   - Print the Kibana URL (ALB DNS name) and bastion IP

To tear everything down, run the same job with `ACTION=destroy`.

## Notes on the Ansible role (as provided)

- Installs Elasticsearch 8.x + Kibana on Ubuntu, single-node cluster per
  instance, `xpack.security.enabled: true`, Kibana anonymous-viewer login.
- Diagram lists Logstash and Filebeat too — this role only covers ES + Kibana.
  If you want those installed as well, add `logstash` / `filebeat` roles under
  `ansible/roles/` and list them in `playbook.yml`'s `roles:` block; happy to
  scaffold those too if useful.
- Only Kibana (port 5601) is exposed via the ALB. Elasticsearch (9200) is
  reachable only inside the VPC (self-referencing rule in `app-sg`) — this is
  intentional; don't expose 9200 to the internet.

## Production hardening ideas (not included by default)

- Put an ACM certificate on the ALB and terminate HTTPS (see comment in `alb.tf`)
- Use one NAT Gateway per AZ instead of one shared NAT (current setup optimizes for cost)
- Replace the `elasticsearch-users`/hardcoded demo passwords with Ansible Vault or AWS Secrets Manager
- Restrict `admin_cidr` to a specific IP/VPN — never leave it open to `0.0.0.0/0`
- Add CloudWatch alarms / an SNS topic for ASG scaling and instance health events
